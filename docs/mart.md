# Витрина `hourly_rentals`: модель и проверки

## 1. Модель

**Выбранный вопрос (основной из Project Brief).** Как погодные условия (температура, влажность, скорость ветра, тип погоды) и календарные факторы (сезон, месяц, день недели, рабочий день/праздник) влияют на суточное и почасовое количество аренд велосипедов в Capital Bikeshare? Витрина хранит разбивку на `casual` и `registered`, поэтому поддерживает и уточняющий вопрос №1 о различии поведения сегментов.

**Гранулярность.** Одна строка `hourly_rentals` — один час наблюдения системы велопроката в конкретную дату. Уровень детализации совпадает со staging и не укрупняется: суточные итоги при необходимости получаются агрегацией часовых строк по `dteday` на следующем шаге контура.

**Ключ.** Естественный составной ключ `dteday + hr`: дата и час однозначно идентифицируют наблюдение. В ЛР №3 по этому ключу проверены пропуски и повторы (0 и 0), поэтому ограничение уникальности не требуется. Технический номер строки не создаётся.

**Меры и правила агрегации.**

| Мера | Единица | Смысл | Агрегация |
|---|---|---|---|
| `cnt` | шт./час | всего аренд за час | суммируется по непересекающимся часам; средние — только с весами по числу часов |
| `casual` | шт./час | аренды случайных пользователей | то же |
| `registered` | шт./час | аренды зарегистрированных пользователей | то же |
| `registered_share_pct` | % | `registered / cnt × 100` | отношение: не суммируется и не усредняется без весов |

`cnt = casual + registered` (правило R5 ЛР №3, 0 нарушений). Время события — `observed_at`, собранный из `dteday` и `hr`. Логическая дата загрузки `source_ingested_on=2026-09-16` хранится в пути объекта и не подменяет время события.

**Структура.** Одна широкая таблица. Все описательные атрибуты (календарь, погода, сегменты) используются как срезы одной и той же меры, справочники малы и не переиспользуются другими витринами, поэтому отдельные таблицы измерений и JOIN не дают выигрыша и только усложнили бы проверки. Гранулярность при этом остаётся согласованной.

**Фильтрация.** Не применяется: в витрину перенесены все 17 379 наблюдений staging. Решения о качестве ЛР №3 (quarantine и флаги) не пересматриваются, флаги переносятся как есть.

## 2. Сопоставление полей

| Поле в `hourly_rentals` | Поле в staging | Преобразование | Смысл, единица или ограничение |
|---|---|---|---|
| `dteday` | `dteday` | `CAST AS DATE` | Дата наблюдения |
| `hr` | `hr` | `CAST AS INTEGER` | Час суток, 0–23 |
| `observed_at` | `dteday`, `hr` | `CAST(dteday AS TIMESTAMP) + to_hours(hr)` | Время события: час наблюдения |
| `season` | `season` | без изменения | Код сезона: 1 зима, 2 весна, 3 лето, 4 осень |
| `season_label` | `season` | `CASE` | Подпись сезона |
| `yr` | `yr` | без изменения | Код года: 0 — 2011, 1 — 2012 |
| `year_num` | `yr` | `2011 + yr` | Календарный год |
| `mnth` | `mnth` | без изменения | Месяц, 1–12 |
| `holiday` | `holiday` | без изменения | Праздник: 0/1 |
| `weekday` | `weekday` | без изменения | День недели: 0 — воскресенье … 6 — суббота |
| `weekday_label` | `weekday` | `CASE` | Подпись дня недели |
| `workingday` | `workingday` | без изменения | Рабочий день: 1 — да (не выходной и не праздник) |
| `day_type` | `workingday` | `CASE` | «Рабочий день» / «Выходной или праздник» |
| `weathersit` | `weathersit` | без изменения | Код погоды: 1 ясно, 2 туман/облачно, 3 лёгкий дождь/снег, 4 сильный дождь/снег/туман |
| `weather_label` | `weathersit` | `CASE` | Подпись типа погоды |
| `temp` | `temp` | `CAST AS DOUBLE` | Нормализованная температура; абсолютные °C не восстанавливаются |
| `atemp` | `atemp` | `CAST AS DOUBLE` | Нормализованная ощущаемая температура |
| `hum` | `hum` | `CAST AS DOUBLE` | Нормализованная влажность |
| `windspeed` | `windspeed` | `CAST AS DOUBLE` | Нормализованная скорость ветра |
| `casual` | `casual` | `CAST AS BIGINT` | Аренды случайных пользователей, шт./час |
| `registered` | `registered` | `CAST AS BIGINT` | Аренды зарегистрированных пользователей, шт./час |
| `cnt` | `cnt` | `CAST AS BIGINT` | Всего аренд, шт./час; основная мера вопроса |
| `registered_share_pct` | `registered`, `cnt` | `ROUND(100*registered/NULLIF(cnt,0), 2)` | Доля зарегистрированных, %; отношение, не мера объёма |
| `quality_status` | `quality_status` | без изменения | Статус качества ЛР №3 (`clean` / `flagged`) |
| `quality_flag` | `quality_flag` | `CAST AS INTEGER` | Флаг качества ЛР №3: 0/1 |
| `quality_rule_ids` | `quality_rule_ids` | без изменения | Идентификаторы правил, пометивших строку |

## 3. Проверки и ограничения

Проверки записанного объекта — раздел «Шаг 5. Проверки записанного результата» в `notebooks/build_mart.ipynb`; там же приведены SQL-запросы и их результаты.

Краткий итог:

- число строк сохранено: 17 379 = 17 379 + 0 исключённых, схема из 26 полей прочитана из S3;
- ключ `dteday + hr`: 0 пропусков и 0 повторов; `observed_at` заполнен;
- меры: 0 NULL; `cnt` от 1 до 977, `casual` от 0 до 367, `registered` от 0 до 886; `cnt = casual + registered` — 0 нарушений;
- диапазоны: `hr` вне 0–23 — 0, `weathersit` вне 1–4 — 0, `registered_share_pct` вне 0–100 — 0;
- флаги ЛР №3 перенесены: все 17 379 строк `clean` / `quality_flag = 0`, расхождений со staging — 0;
- пригодность для вопроса подтверждена срезом по погоде: средняя часовая аренда 204,9 (ясно), 175,2 (туман/облачно), 111,6 (лёгкие осадки), 74,3 (сильные осадки, 3 часа);
- JOIN не используются, поэтому проверки кардинальности и ненайденных соответствий не применяются.

**Ограничения.** Данные агрегированы по всей системе, без станций; период только 2011–2012; погодные показатели нормализованы; витрина — статичный снимок наблюдений, а не история изменений. `registered_share_pct` — отношение, его нельзя суммировать или усреднять без весов. Суточные итоги в витрине не хранятся, чтобы не смешивать часовую и дневную гранулярность.
