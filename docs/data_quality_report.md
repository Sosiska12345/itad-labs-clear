# Отчёт о качестве данных: raw → staging

## 1. Контекст

Аналитический вопрос: как погодные условия и календарные факторы влияют на суточное и почасовое количество аренд велосипедов Capital Bikeshare; различается ли поведение `registered` и `casual` пользователей.

Проект — ITAD Labs, контур «Источник → raw → staging → mart». Исходный файл `hour.csv` (UCI Bike Sharing Dataset) загружается DAG-ом `ingest_raw` в raw-слой SeaweedFS с логической датой `2026-09-16`.

Входной S3-путь raw: `s3://raw/hour_data/ingested_on=2026-09-16/hour.csv`.
Выходной префикс staging: `s3://staging/hour_data/source_ingested_on=2026-09-16/`.

Одна строка — один час наблюдения: дата, час, календарные и погодные признаки, количество аренд `casual`, `registered`, `cnt`. Бизнес-ключ — составной `dteday + hr`.

Значимые наблюдения:

1. Пропусков и повторов по бизнес-ключу нет, поэтому raw можно напрямую проверять правилами и готовить staging без ручного восстановления ключей.
2. Распределение по часам имеет выраженную внутрисуточную структуру: средний `cnt` минимален в 4:00 (6.4), растёт к утреннему пику в 8:00 (359.0) и достигает максимума в 17:00 (461.5) и 18:00 (425.5). Это подтверждает гипотезу о маятниковой структуре спроса и важно для анализа календарных факторов и сегментов `casual`/`registered`.
3. Средний `cnt` зависит от типа погоды: 204.9 при `weathersit = 1`, 175.2 при `2` и 111.6 при `3`. Для `weathersit = 4` всего 3 наблюдения, поэтому вывод по этой категории делать нельзя.
4. Средний `cnt` в рабочие дни выше (193.2), чем в нерабочие (181.4), что согласуется с поездками на работу и обратно.

## 4. Подготовленные данные

Записаны объекты:

- `s3://staging/hour_data/source_ingested_on=2026-09-16/staging.parquet` — 17 379 строк, 372 095 байт;
- `s3://staging/hour_data/source_ingested_on=2026-09-16/quarantine.parquet` — 0 строк, 381 байт (файл создаётся всегда, даже при нуле записей).

Проверка баланса строк: `raw = staging + quarantine`; в данном прогоне `17 379 = 17 379 + 0`.

Преобразования:

- `dteday` приведён к `DATE`; числовые поля приведены к `BIGINT`/`INTEGER`/`DOUBLE`;
- в staging добавлены `quality_status`, `quality_flag`, `quality_rule_ids` (итого 20 колонок: 17 исходных + 3 служебные);
- записи с critical-нарушениями не попадают в staging, а попадают в quarantine с `quality_rule_ids` и `quarantine_reason` (19 колонок: 17 исходных + 2 служебные);
- `quarantine.parquet` создаётся всегда, даже при нуле записей.

Результат критических правил на staging: `R1_UNIQUE_KEY`, `R2_CNT_NOT_NULL`, `R3_HR_RANGE`, `R5_CASUAL_REGISTERED_CNT` — 0 нарушений; дублей `dteday + hr` — 0.

## 5. Воспроизводимость и ограничения

Ноутбук: `notebooks/profile_quality.ipynb`. Запуск выполняется сверху вниз, параметры и пороги заданы в отдельной ячейке. При первом и повторном выполнении количества строк совпадают: raw — 17 379, staging — 17 379, quarantine — 0.

Стенд поднят из корня проекта командой `docker compose up -d --build`. Сервисы: `seaweedfs` (`chrislusf/seaweedfs:4.48`, режим `weed mini`, S3 API на `localhost:8333`, бакеты `raw`, `staging`, `mart`), `airflow-db` (PostgreSQL 16.8), `airflow-scheduler` и `airflow-webserver` (Airflow 2.10.5, образ собран из `airflow/Dockerfile`). Веб-интерфейс Airflow доступен на `http://localhost:8081` (порт 8080 на хосте занят другим приложением), учётная запись `airflow` / `airflow`.

DAG `ingest_raw` запущен вручную на логическую дату `2026-09-16` (`run_id = manual__2026-09-16T00:00:00+00:00`); задачи `wait_for_primary_source` и `load_to_raw` завершились успешно. Файл в raw загружен самим DAG-ом по пути `s3://raw/hour_data/ingested_on=2026-09-16/hour.csv` (1 156 736 байт, MD5 `d50bd5a6f55131e72a7bedc334e2fce1`), байты совпадают с `data/source/hour.csv`.

DuckDB 1.1.3 читает raw и пишет parquet через расширение `httpfs` (`s3_url_style = 'path'`, `s3_use_ssl = false`).

Ограничения:

1. Погодные показатели `temp`, `atemp`, `hum`, `windspeed` нормализованы, выводы интерпретируются в относительных единицах.
2. Данные агрегированы по всей системе Capital Bikeshare и охватывают только 2011–2012 годы; нет разреза по станциям и текущего состояния сервиса.
3. Категория `weathersit = 4` представлена 3 наблюдениями — статистически значимых выводов по ней нет.
